# 生存端评估引擎 设计文档（待研究）

- 日期：2026-09-05
- 状态：设计蓝本（在输出端补全后启动；当前仅落方案）
- 归属：wows-replay-parser skill（分析层），数据源对接 wows-replays / wows-battle-world
- 目标：评价「怎么活下来的」——生存质量 + 「活着才有输出」的生存→输出耦合，产出专业走位/规避/自救建议。

## 1. 问题与动机

表现分两端：**输出端**（弹着已成事实后的命中质量，已实现）与**生存端**（活着本身）。输出端已能回答「这发命中质量/该不该换弹」；生存端要回答「你怎么活下来的 / 哪里暴露 / 怎么规避 / 受到的自救做得好不好」，并解释「活下来才有的输出」。

同为低血/低输出的表层症状，根因可完全不同：早死（一局没输出）vs 全程满血但贪刀被迫保守（输出被掐）。生存端要区分「被打死 = 走位/暴露问题」与「被集火是队友没扛/你作为卖点」——只报有证据支持的结论。

## 2. 机制不变式

- **生存先于输出**：输出端评估以「打出去了」为前置；生存端以「活着 / 血量 / 暴露」为前置。二者唯一耦合点是生存状态对输出的抑制（血量低 → 被迫躲 → DPM 掉）。
- **受伤≠失误**：被打伤可能是好事（吸引火力 = Agro），也可能是暴露。要分「该扛的（掩护队友 / 卖血换位）」与「白挨的（无掩体 / 无意义露头）」。
- **只报可测证据**：暴露度、受击、走位、自救均可测；「敌人才是冲你来的」标注「需事件级」，不臆断。

## 3. 数据源（wows-battle-world / wows-replays 已解码）

| 数据 | 出处 | 用途 |
|---|---|---|
| `self_damage_stats`（`DamageStatCategory::Agro`） | 0x22 damage stat | 潜在伤害/被瞄准的「火力」总量 |
| `hit_history`（`victim_entity_id == self`） | shot kills | 被打命中：来源、武器（弹种/副炮/鱼雷）、命中类型、命中点（含 `victim_pose`/`terminal_ballistics`）→ 据此估吃到伤害 |
| `burn_state_changes` / `burn_state_observed` | burningFlags | 着火次数/持续 |
| `active_consumables` | 消耗品 | DCP / 维修小组 / 烟 的使用时机与是否及时 |
| `deaths_by_victim` / `battle_result` / `finish_type` | 结算 | 是否死亡、何时、终局类型 |
| 位置时间线（`Position` 0x0a + `Transform3d`/`MinimapPlacement`） | 包流 | 走位、暴露、kiting 角、与掩体距离（**需新增导出**） |
| HP 时间线 | vehicle HP | 血量管理、濒死时刻（**需新增导出**） |
| `visibilityFlags` / `DetectedByHydrophone` | 侦测 | 被多少敌舰点亮、为何（H1/M4 缺口） |

**关键缺口**：`BattleReport` 有 `presence()`（观测窗口）但**无位置时间线 / HP 时间线**；生存端核心里程碑 S2/S3 需新增这两种历史导出（类似 M1 的 `hit_history`/`salvo_history`）。`visibilityFlags` 逐目标谁点亮（H1/M4）仍未解，用于「被集火 vs 被点亮」的区分。

## 4. 维度与指标

| 维度 | 证据 | 判定（示例） |
|---|---|---|
| 受击/暴露 | 被打命中时序、`Agro`、位置（离掩体/无掩体、被几舰有视线） | 处于无掩体且被 ≥3 舰集火 → 暴露/走位问题 |
| 伤害承受 | 被打命中估伤、HP 下降、着火/进水 | 被过穿/核心/火烧的重伤占比；火焰是否及时 DCP |
| 规避/走位 | 位置时间线（kiting 角、机动、掩体距离） | 长期不对正敌方主炮 / 贴山 / 保持外切角度 → 走位好 |
| 自救 | `active_consumables`（DCP/heal）时机 vs 着火/受击 | 着火后未及时 DCP / heal 提前空放 → 自救差 |
| 死亡/濒死 | `deaths_by_victim` 时刻 + HP 最低点 + 该时刻的受击来源 | 被谁在哪个方位集火致死 |
| 生存→输出耦合 | 输出端 DPM/评分随血量/时段变化 | 满血段 DPM 高、残血段被迫保守 → 「活着才有输出」 |

## 5. 里程碑

- **S1（用现有数据）**：生存画像——被打命中（来源/武器/命中类型/落点）+ 估伤 + 着火/进水 + DCP/heal + 死亡 + `Agro`；给出 0-100 生存分与「受击/自救」结论。复用 `hit_value` 的 `estimate_damage`（对 `victim==self` 命中）。
- **S2（新增位置时间线导出）**：暴露/kiting/掩体判定。属 M1 式新导出（记录 `Position` 到历史）。
- **S3（新增 HP 时间线）**：血量管理、濒死时刻、血量 vs 输出耦合。
- **S4（整合评分）**：生存分 + 生存→输出耦合结论；与输出端报告合并成「整局表现」。

## 6. 评分思路（S1 可先行）

生存分（0-100）= 加权：
1. **受击规避**：实际吃伤 vs 被瞄准火力（`Agro`）——吃伤低、回避高 → 好。
2. **自救**：DCP/heal 覆盖有效、着火未失控。
3. **死亡/濒死**：无死亡且无濒死骤降 → 好；早死末段 → 差。
4. **走位/暴露**（S2）与 **HP 管理**（S3）。

判定分级沿用输出端：`已证实` / `净额支持` / `疑似（需事件级）` / `无证据`。

## 7. 不自欺规则

- 被集火 ≠ 一定是你的错：队友不扛、你是卖点也能解释，标注「可能是团队取舍」。
- 「暴露」必须由**位置 + 敌舰有视线**证据支撑，不能只凭受伤。
- 「自救差」要按**消耗品可用而没用 / 用了但时机错**区分（用错 = 差；没得用 = 资源问题，非失误）。
- 只报证据链（测量 + 阈值），不臆断；与输出端共用术语表与 ADR。

## 8. 依赖与风险

- 位置/HP 时间线导出需扩展 battle-world（新的 history 记录 + report 暴露），涉及核心层，改动类似 M1。
- `visibilityFlags` 逐目标（H1/M4）未解锁，限制「被点亮」精度；不可行时标「需数据」。
- 版本差异沿用现有 `fields_resolved=false` 降级，不做虚假归因。

## 9. 验证

- 用已知案例：一局满血高输出（应判「走位好、存活好」）、一局早死（应判「暴露/被集火致死」）、一局被火烧废（应判「自救差」），人工核对并标置信度。
