剧情（行动）经验机制：模型、系数与可复现验证（精英版）

面向追求可复现、可挑错的读者。全程使用“基础经验”（不含高账 1.65x、首胜）口径。

1. 结论速览

剧情经验分配可分解成“保底均分 + 舰种加权的吃船效率”，总经验池主要由“地图 + 星级 + 输赢”决定。

  • 总经验池：team_raw ≈ base[scenario] × 1.09^stars × (赢 ? 1 : 0.44)，目标项拟合 R²=0.9595。

2. 数据与口径

  • 来源：本地回放 + replayswows.com 分享站 PVE 回放，按 (arena_id, account_id) 去重。
  • 规模：2060 局（新剧情 317、老剧情 1743），14420 玩家行。
  • 舰种分布：BB 6217、CL/CA 5726、DD 1845、CV 260、SS 372。
  • 经验口径：一律用回放的 raw_exp（= 局主 init_economics.exp，即基础经验）。
  • WG API 的 oper_solo.xp 含高账 1.65x，对齐时需 ÷1.65。
  • 1.5x 是随机 PvP 胜方加成，与剧情无关。
  • 已知偏置：抓取源赢局偏多（败局仅 151/2058 ≈ 7.3%），且无超时败局样本，见第 7 节。

3. 模型一：经验分配

3.1 吃船效率

对每艘敌舰累加「你对它造成的伤害 ÷ 它的最大 HP」：

ship_eff_i = sum_over_enemies( damage_i_to_k / max_hp_k )

击沉船全队合计约 1；未沉船按比例计，剩余血量不计入任何人。

提取自回放 playersPublicInfo[attacker].interactions[victim]（索引取

CLIENT_VEH_INTERACTION_DETAILS 的 damage_* 字段），victim 血量取

CLIENT_PUBLIC_RESULTS_INDICES.max_health。

3.2 分配式

contribution_i = ship_eff_i + lambda * (scouting_damage_i / 100000)

XP_share_i = a/n + (1-a) * K[class_i] * contribution_i
                       / sum_j(K[class_j] * contribution_j)

base_XP_i = XP_share_i * team_base_XP
  • a：均分地板（约一半经验人人平分）。
  • lambda：点亮伤害在“贡献”里的权重（每 10 万点亮 = 1 个船等效）。
  • K[class]：舰种在效率项上的权重，CL/CA 固定为 1.00。

3.3 拟合方法

  1. 网格搜索 a ∈ {0,0.02,...,0.92}、lambda ∈ {0,0.1,...,2.0}。
  2. 每个格点上，用「局内去均值」的 log-ratio 回归估计 K：

Y = log(xp_share - a/n) - log(contribution)，对舰种哑变量做 OLS（DD 为基准，局内 demeaning 消除局固定效应），K = exp(coef)。

  1. 以全样本 SSE 最小选 (a, lambda)，对应 K 即为点估计。

4. 潜艇 1.75 辨析

两个“矛盾”的数字其实是两个问题：

  • 社区 1.75x = 相对驱逐的效率权重。实测 K[SS]/K[DD] = 1.68 [1.58, 1.78]，成立。
  • 早前“潜艇只多 +10%” = 相同伤害下的经验比。潜艇效率与伤害不成正比，该口径不是对 1.75 的正确检验。

非参数交叉验证（局内把每艘潜艇与“贡献值”最接近的水面舰配对，比保底外份额）：

合并中位数 1.403 落在 K[SS]/K[水面均值] 附近，佐证 K[SS] 不是回归伪影。

新老剧情差异（随机性）：新剧情地图更随机，削弱潜艇“背板”：

潜艇效率占比 12.6%→8.6%（约 -46%），伤害 169.6k→108.9k（约 -36%）。这只降低“贡献量”，

不改变 K[SS]（新老均在 1.38~1.42 之间）。

5. 模型二：总经验池

5.1 式与系数

对 log(team_raw) 做 OLS，含场景固定效应：

team_raw ~ base[scenario] * 1.09^stars * (win ? 1 : 0.44)
项coef95% CI倍数
stars（0~5）0.0865[0.0829, 0.0903]每星 ×1.090
secondary_completed0.0226[0.0185, 0.0264]与星级冗余，弃用
is_win0.8178[0.7947, 0.8367]赢/输 ×2.263；输/赢 ×0.442
team_eff（每船等效）0.0031-×1.003，可忽略
n_inactive（挂机/暴毙合并口径）-0.0283-每人 ×0.972
  • 目标项（场景 + 星级 + 胜负）R²=0.9595；加入队伍效率/伤害仅升到 0.9709 → 池子是目标导向。
  • base[scenario] 地图基线：常态约 7500~10000；旗舰(Flagships)为限时模式，约 11800~14006（约高级的 1.3~1.4 倍），不计入常态。
  • 星级均池（合并样本）：0星≈2873、1星≈6668、2星≈7436、3星≈8175、4星≈8782、5星≈9577。

5.1.1 挂机与暴毙拆开看

replay 公开数据里没有队友的 is_afk / is_ineffective（这些在服务器私有数据，回放只带记录者自己的那份），所以只能行为近似区分：

行为判定近似池子倍数
挂机 / 逃兵伤害 0、击杀 0、点亮 0，且早期阵亡×0.927（每人约 -7.5%）
暴毙有少量输出但早死×0.970（每人约 -3%）

该拆分的“零贡献”样本极少（2060 局仅 5 局），且多为只点亮的航母/潜艇或失败局，不是典型挂机。因此玩家反馈的“挂机扣全队 1/7（-14.3%）”在当前样本未证实，观测更接近 -7.5%；要坐实 1/7 需带服务器 AFK 判定的样本。相关脚本：scripts/analyze_afk_death.py。

5.2 finish_type 无法再分

样本 finish_type 与胜负完全共线：

finish_type胜负n
PROTECTED_TARGETS_DESTROYED赢1907
BASE（目标被毁）输151

无 TIMEOUT(13) / SCORE_ON_TIMEOUT(18) 样本，抓取源又偏赢局。因此「超时输 vs 被团灭输」

的惩罚差异在当前数据下不可识别；×0.44 为败局整体惩罚。
